原多引擎计划的 A–F 阶段已有主要实现：能力化 adapter、manifest/registry、`window.searchApi`、旧连接读取兼容、ES/OpenSearch 工作区、Solr 原生查询/Schema/uniqueKey 写入，以及有限批次导入导出。接手时类型检查和 21 文件 / 209 项测试通过，但未完成真实服务器、完整 UI 和打包验收。

## 本轮改动

- IPC：文档、资源、任务与导入请求先做运行时校验，再解析 adapter 或产生副作用；修复错误处理前解构空参数、对非字符串 ID 调用 `trim()` 等异常逃逸。非法请求返回固定安全错误，不泄露输入或 transport 异常。
- URL：ES/OpenSearch CRUD 拒绝文档 ID `.`/`..`，防止 URL 规范化改变请求目标。Solr 的 ID 在请求体中处理，继续保留其原生语义。
- 传输：预览增加可选 `connectionId`，preload 沿用共享请求类型，无需新增 channel。预览与执行按 manifest 选择相同解析规则；Solr 中名为 `fields`、`_source`、`_id` 的普通字段不再被拆掉。ES/OpenSearch CSV `_id` 列还原为文档 ID，不再混入 source。
- Renderer：cluster/version、mapping/settings、aliases/templates 和 shards 增加请求序号检查；切换、取消选择、重置时旧请求失效。元数据和查询的 IPC 拒绝会结束 loading，并显示固定安全消息。
- Schema：ES/OpenSearch 递归返回 object/nested、多字段及 ES 6 多 mapping type；保留 nested 祖先、multi-field 来源和原始 mapping；支持别名返回实际索引键。

主要文件：`src/main/services/requestValidation.ts`、`document.service.ts`、`resource.service.ts`、`import.service.ts`、`transferFiles.ts`，`src/main/adapters/elasticsearch/documentApi.ts`、`schemaApi.ts`、`index.ts`，共享 `ipc.ts`/`searchEngine.ts`，renderer `workspace.store.ts`/`ImportPanel.tsx` 以及对应回归测试。

## 剩余验收与计划差异

1. ES 6/7/8/9、OpenSearch 1/2、Solr 8/9 的真实探测、权限、查询、读写、传输、错误和取消矩阵仍是发布门槛；fixture 不证明 live 兼容性。
2. Electron 仍需完整 loading/empty/error/success/cancellation、快速切换连接/资源和 destructive-confirmation 验收。
3. 网络可用时重新执行默认 pack 与 Windows 安装包检查。离线 smoke 即使成功，也不代表签名、资源编辑或安装器已验收。
4. 阶段 B 中的自定义 TLS/代理/证书配置、扩展认证和查询历史等尚未完整实现。当前认证仍是无认证和 Basic；TLS 配置、系统凭据库迁移、PIT、任务恢复和插件按后续路线处理。
5. 旧 index/alias/template IPC 的全面运行时校验、统一路径策略和权限能力细分仍可继续推进。本轮没有把所有 P0–P3 目标标记为完成。
6. `ai-dev-steps/` 当前被 `.gitignore` 忽略；本记录和 `docs/plans/` 放在可跟踪目录，便于再次中断后恢复。
