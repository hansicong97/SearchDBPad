# 紧凑布局与主题设置变更记录

日期：2026-10-18。

阶段说明：下文保留 UI 实现阶段的范围与验证记录，当时尚未分配版本和打包。该改动现纳入 v0.4.1；本次发版验证与下载内容见 [v0.4.1 发布说明](v0.4.1.md)。

本记录描述 0.4.0 之后的当前工作区改动，尚未分配新版本号或生成新的发布下载包，不改写历史 0.4.0 发布说明。

## 行为变化

- 移除内容区顶部的 SearchDBPad 名称、简介和主题切换按钮，释放原来 56 px 的布局高度。产品介绍继续通过“帮助 → 关于 SearchDBPad”查看。
- “文件”菜单新增“设置…”，打开应用内设置弹窗。关闭按钮、Esc 和“完成”均只关闭弹窗；主题更改立即生效。
- 设置提供“浅色”“深色”“跟随系统”，并在重启后保留所选偏好。旧版本已保存的浅色/深色选择继续使用；没有保存记录时默认跟随系统。
- 跟随系统时动态响应系统外观变化；手动固定浅色/深色时不受系统外观变化影响。
- 应用内容、连接侧栏和 Monaco 编辑器使用同一个有效主题。工作区内部使用剩余可用高度，保留原有任务入口和连接操作。

## 实现范围

- `src/shared/ipc.ts` 增加主进程通知事件 `AppOpenSettingsEvent`（`app:openSettings`），载荷为 `{ section: 'appearance' }`。
- 原生菜单通过窗口的 webContents 发送事件；preload 仅暴露类型化的 `onOpenSettings` 订阅，返回清理函数，不向 renderer 暴露原始 IPC 事件或 Node API。
- `App.tsx` 移除品牌顶栏并管理设置弹窗；`SettingsModal.tsx` 提供外观选择。
- 主题状态区分保存的 `mode`（light/dark/system）与实际 `resolvedMode`（light/dark），使用系统外观监听并在卸载时清理。
- 保持原有 localStorage 主题键与浅色/深色记录兼容，不新增依赖，不更改连接/收藏等业务数据。

环境：Windows x64，Node.js 22.22.0，Electron 32.3.3；保持现有依赖与版本号。

| 重启恢复 | 将偏好设为深色后正常退出并用同一测试配置重启，界面与设置选中项恢复为深色；再次选择跟随系统可恢复当前浅色外观 |

| 安装器与 live server | 本轮未运行 `npm run pack` / `dist:win`，未执行真实搜索服务器或安装/卸载/升级验收 |

桌面验收使用工作区内临时 runner 和独立 userData，应用实例的系统外观固定为浅色以核对保存偏好与跟随行为；不是修改 Windows 全局外观。临时 runner/配置在验收后清理，不属于发布内容。原生菜单/标题栏仍遵循操作系统样式，应用主题设置作用于 renderer 内容。

默认受限进程启动返回 `0x80000003`；改为允许的本地 Electron 启动后完成以上窗口检查。该启动限制不作为产品功能失败，也不替代安装器验收。
