# 查询工作台升级讨论草案

- 日期：2026-10-18
- 状态：需求讨论中；本文尚未作为实施计划或发布承诺
- 代码基线：SearchDBPad 0.4.0
- 关联文档：[后续产品方向](2026-10-18-product-directions.md)

## 1. 本文用途与当前建议

这份草案把“查询工作台升级”拆成可以逐项讨论的产品行为。用户已要求先记录方向、细化工作台，再沟通细节；因此下文的默认值、界面安排、阶段和数据模型均是建议，仍需讨论确认。版本号、工期和最终首期范围暂不指定。

建议先完成“写过的查询能留下、切换后能继续、执行目标能看清”的工作闭环，再完善字段辅助、结果表格和参数模板。

本文讨论三个递进阶段：

| 阶段 | 主要解决的问题 | 建议内容 |
|---|---|---|
| A1：保存与继续 | 查询、草稿和上下文容易丢失 | 查询历史、草稿自动保存、按上下文恢复、执行/取消状态、收藏兼容 |
| A2：编写与阅读 | 字段靠记忆，结果不便浏览 | Schema 字段辅助、简单查询类型提示、可配置结果列、表格/JSON 视图 |
| A3：参数与复用 | 相似查询反复复制修改 | 参数化模板、执行前预览、兼容连接间复用 |

首期建议选择 A1。A2、A3 也在本文说明，便于提前评估方向；是否合并进首期仍待确认。

## 3. 用户场景与成功标准

| 场景 | 预期行为 | 可观察的成功标准 |
|---|---|---|
| 昨天写了一半，今天继续 | 重启后恢复查询文本和目标，等待用户执行 | 未执行的有效或无效 JSON 草稿都能恢复 |
| 在两个索引间排查 | 切换资源后保留各自草稿，返回时继续 | 不需要另开文本文件保存查询 |
| 找回上周运行过的条件 | 按连接、资源、时间、状态和关键字查历史 | 找到后可在新标签打开，不自动请求服务器 |
| 修改查询后再看旧结果 | 清楚区分编辑中的条件与上次实际执行的条件 | 不会把旧结果误认为新文本的结果 |
| 不熟悉字段名称 | 根据 Schema 搜索字段、查看类型和提示 | 减少拼写错误，同时保留手动输入能力 |
| 阅读有很多字段的文档 | 选择业务列，并保留查看完整 JSON 的入口 | 重开同一上下文可恢复列视图 |
| 每天只改订单号或时间 | 用带类型参数的模板生成查询 | 提交前能查看最终查询及真实目标 |

不以功能数量作为验收目标。讨论确认后，应选取代表性任务，比较操作步骤、找回查询的耗时和意外丢失草稿的次数；目前没有用户样本，本文不设未经验证的提升百分比。

## 4. 工作台形态的三个选择

| 方案 | 使用方式 | 收益 | 成本与取舍 |
|---|---|---|---|
| 方案一：按连接和资源保存 | 保留现有资源详情入口；切换侧栏时切换对应的查询空间 | 接近现有习惯、改动较集中、目标明确 | 同时观察多个资源仍需来回切换 |
| 方案二：全局独立工作台 | 每个标签独立选择连接和资源，与侧栏选择分离 | 方便多连接、多资源并行 | 需要重做导航、目标绑定、元数据和后台请求管理 |
| 方案三：逐步演进 | 首期按上下文保存；以后加入“复制到其他连接/在独立标签打开” | 先解决丢失问题，再按使用反馈扩展 | 需要为标签预留明确目标，但不提前建设复杂项目系统 |

**建议方案三，首期采用方案一的界面。** 是否直接做全局工作台，是后续讨论的第一个决策。

建议区分两个身份：

- 导航上下文：侧栏当前选择的连接、资源和查询语言，决定当前显示哪组草稿。
- 执行目标：标签明确保存的连接、目标资源和语言。保留现有编辑目标的能力，不把新侧栏选择静默覆盖到标签上。

首期按导航上下文保存标签组；标签中手动改过的执行目标也随草稿保存。Schema、历史、结果列视图按实际执行目标解析。目标改变后重新校验，旧结果应失效或被明确标为上次执行结果。

### 4.1 建议的信息布局

```text
现有连接/资源侧栏 | 当前连接 / 引擎 / 查询语言 / 实际执行目标
                  | 查询标签：订单排查 | 最近异常 | +
                  | 格式化  执行/停止  收藏  历史  模板  草稿保存状态
                  | 查询编辑区 / Solr 原生参数表单
                  |-----------------------------------------------
                  | 执行状态 / 服务端耗时 / 客户端总耗时 / 命中摘要
                  | 表格 | JSON | 原始响应     列配置
                  | 查询结果
```

历史建议先用可搜索的抽屉，避免增加一层常驻侧栏；字段辅助先使用可收起面板。编辑区和结果区建议支持拖动分隔线，记住布局比例；窄窗口自动收起辅助面板。具体尺寸和布局在范围确认后再画原型。

## 5. A1：保存与继续

### WB-01：草稿和标签恢复

建议保存标签 ID、标题、顺序、查询文本/表单状态、语言、导航上下文、执行目标、最近活动时间和活动标签。

- 草稿允许不完整或不合法的 JSON；执行时再校验。
- 编辑后短暂延迟自动保存；建议起点为 800 ms，需在实现时验证输入流畅性。
- 切换上下文、关闭标签和正常退出时尝试提交待保存内容；异常退出只能恢复最近一次已成功写入的版本。
- UI 区分“保存中”“已保存”“保存失败”。失败保留内存文本，并提供复制和重试入口。
- 重启仅恢复文本、目标和视图状态；查询结果、loading 状态、requestSeq、Scroll/PIT/cursor 等运行时数据不落入草稿。
- 恢复后不自动连接或执行查询。最近上下文可作为导航提示，网络请求仍遵循用户的连接操作。
- 连接被删除、资源不存在或暂时离线时，草稿保留为不可执行状态，允许复制或重新绑定。
- 连接 ID 相同但地址或引擎发生修改时，提示重新确认执行目标。避免旧草稿在新服务器上直接运行。

关闭已保存标签时，建议从“打开的标签”列表移除，同时暂存到最近关闭列表，支持撤销关闭；保留数量和时长待确认。该列表受同一查询正文保存开关约束。若尚未保存成功，关闭前提供重试、复制或放弃选择。

简单查询/Solr 表单也应按上下文保存表单状态。首期是否要求与 DSL 一样支持多个标签，单独讨论，避免为了统一外观改变原生查询模型。

### WB-02：持久化查询历史

草稿记录“正在写什么”，历史记录“实际执行过什么”，收藏记录“主动保留什么”，三者分别管理。

**记录时点与内容：**

1. 用户主动执行、主进程完成请求校验并接受执行时，生成执行 ID 和不可变的查询快照。
2. 记录来源入口、语言、连接 ID、资源、开始时间、实际提交的查询、执行状态。
3. 完成时补充客户端耗时、引擎返回的 `took`、总命中数及其 `eq/gte` 关系、安全错误码。
4. 当前受支持的查询入口都应进入历史：简单查询保存生成后的原生请求和必要表单值；Solr 保存 `q`、`fq`、`sort`、`start`、`rows` 等原生参数。
5. 本地语法错误、仅格式化、打开历史、默认文档浏览及后台元数据刷新不产生历史。

**状态语义：**

| 状态 | 含义 |
|---|---|
| 运行中 | 主进程已接受，尚未取得终态 |
| 成功 | 取得有效响应；零命中仍是成功 |
| 失败 | 校验通过后执行失败；记录可公开的错误摘要 |
| 已取消 | 当前请求取消流程已结束；不据此保证服务器计算即时终止 |
| 已中断 | 上次进程退出时未取得终态；重启后不自动重跑 |

历史的终态由主进程执行生命周期更新，不能依赖当前标签是否仍存在。导航取消导致页面不接收结果时，也应正确结束这次历史记录。

**查找与复用：**

- 默认筛选当前执行上下文，允许显式切换到全部历史；支持时间、状态、连接、资源及文本关键字筛选。
- 列表展示时间、连接/资源、语言、简短条件摘要、状态、耗时和命中数。
- “在新标签打开”是默认动作；若要覆盖当前草稿，需要明确选择。
- 恢复历史不直接执行。原连接不可用时先选择兼容目标，并重新显示完整目标。
- 每次执行保留独立记录；可在展示层折叠连续重复查询，避免合并后丢失时间和状态。
- 支持删除单条、清空当前连接历史和清空全部历史；批量清空有明确确认。

**容量建议，均待确认：** 首期按条数、保存天数和总字节数共同控制，例如 500 条、30 天、10 MiB，先达到任一上限就清理最旧的自动历史。大查询超过单条限制时提示本次仅保留摘要，不能静默截断为可执行正文。收藏不随历史淘汰。

### WB-03：收藏兼容与加载

保留现有收藏入口和已存内容，首期优先补足语言和来源上下文，不重建第二套收藏系统。

- 收藏仍是用户主动保存的可复用查询；历史可以“另存为收藏”，不自动升级为收藏。
- 语言是兼容判断的必要字段，连接/资源可以作为来源与建议目标。
- 旧收藏缺少语言时，保留原始记录并标注 legacy DSL 来源；迁移规则需结合旧版本行为确认，不通过出现 `q` 或 `query` 等键来猜测语言。
- ES/OpenSearch 之间允许在语言一致时加载，并提示服务器版本/字段能力可能不同；语法兼容不代表执行一定成功。
- Solr 收藏保留原生参数；不将 ES DSL 自动改写成 Solr，也不反向改写。
- 加载到新标签后显示目标，用户再主动执行；保留现有保存/使用/删除流程及服务层 update 兼容。是否在首期新增收藏重命名/编辑 UI，作为范围选择确认。
- 数据格式迁移需要版本、备份和失败回退；旧连接缺少 `engineType` 时仍按仓库现有 ES 兼容规则读取。

### WB-04：执行、停止与结果归属

每次执行固定查询文本、目标、语言和请求身份。编辑器后续修改不能改变这次正在运行的请求，也不能改写其历史快照。

- 首期建议保留当前“编辑查询即取消该标签旧请求”的习惯，并让 UI 显示正在结束旧请求的状态；后续是否允许编辑时继续执行，作为备选行为讨论。
- 同一标签重复执行时取消旧请求，并用新的执行 ID/请求序号隔离结果。
- 不同标签保留独立结果与错误状态；全应用并发上限及排队策略待实现评估，首期不主动并发执行所有恢复标签。
- 切换连接/资源时保存草稿并取消离开上下文的请求；在同组标签间切换可让当前请求继续，返回时显示其状态。
- 关闭标签会取消该标签请求；完成或取消后的结果不能写入已关闭、已换目标或重新创建的标签。
- 明确区分正在运行、无命中、失败、取消和未执行；保留旧结果时标明它对应的执行时间和条件。
- “停止”结束本次查询，不删除草稿。取消失败或暂未确认时不能先显示取消成功。
- 建议在编辑器有焦点时支持 `Ctrl+Enter` 执行；停止按钮保持可见。格式化复用 Monaco 的标准动作，快捷键在 UI 标出。

持久化历史和草稿失败时，不应把一次成功的服务器查询改报为查询失败。分别显示查询结果与本地保存提示；初次读取本地数据失败时也要保留手动查询入口。

## 6. A2：编写与阅读

### WB-05：Schema 感知的字段辅助

复用现有 Schema，不为字段辅助新增直接访问引擎的 renderer 网络路径。

- 字段列表支持搜索，显示类型、完整字段路径及可用元信息。
- 简单查询提供字段选择与操作符提示；未知字段保留手动输入能力。
- 数值、布尔、字符串、日期按字段类型处理。例如编号 `000123` 在字符串字段中保留前导零；超出 JavaScript 安全整数范围的值不得无提示转成不精确数字。
- DSL 补全先覆盖字段名和少量常见片段，说明支持边界；不承诺首期拥有所有版本的完整 API 语义校验。
- object/nested/multi-field 需要不同提示；不能把选择 nested 字段直接等同于自动生成正确 nested 查询。
- Solr 保留字段类型、multiValued、stored 和 uniqueKey 等自身语义；动态字段只能作为模式提示，不能假设已经枚举出所有实际字段。
- Schema 无权限、加载失败或过期时提示重试，编辑器与已有查询仍可使用。目标改变后废弃旧 Schema，请求返回时核对目标和请求序号。
- 首批字段辅助建议针对单一具体资源。标签目标为别名、通配表达式或多个资源时，只有确切解析出覆盖资源和字段类型冲突后才能提供确定的类型提示；首期可降级为手动输入并说明原因，不拿侧栏单一资源的 Schema 代替。
- 补全不覆盖用户查询，不因为选择字段而自动请求文档样本。

### WB-06：结果列与双视图

建议默认保留 ID 与完整文档视图，同时允许选择字段列、调整顺序和宽度，按实际执行上下文记住列配置。

- 字段值区分不存在、`null`、空字符串、零、`false`、对象和数组。
- 嵌套对象使用明确的路径片段取值；字面含点的字段名与对象路径不能混淆。
- 数组、nested 文档和多值字段首期以折叠 JSON 或数组摘要展示，不自动拆成多行。
- 引擎元数据 ID 与 source 中同名业务字段分开表示；Solr 的 uniqueKey 按其真实字段使用。
- Schema 有字段不意味着该字段会出现在结果中；Solr 非 stored 字段、源过滤等情况显示未返回，不伪造空值。
- “表格”“文档 JSON”“原始响应”复用同一份结果，不因切换视图重新执行查询。
- 列配置只影响展示，不自动修改 `_source`/`fl`、服务端排序或查询正文。
- 首期表格排序如仅作用于已加载结果，必须标明范围；服务端排序需要生成可见的新请求并重新执行。
- 命中总数保留 `eq/gte` 信息；分开显示“本次已加载 N 条”和“总命中 M/至少 M 条”。
- 现有 DSL 表格页码只浏览当前已返回 hits，不能把换页描述成已实现全量服务器分页。自动 `search_after`、PIT、cursorMark 浏览另行定义范围。

聚合结果继续保留原始响应入口。首期不把任意 aggregation 结构自动转为业务图表。

## 7. A3：参数化模板与跨连接复用

### WB-07：带类型的查询模板

先确定模板与收藏的关系。建议模板是“带参数定义的收藏”，共享管理入口，而不是新增一套互不相通的查询库。

示例：订单查询模板定义 `orderId: string`、`startTime: datetime`；用户填写参数后查看最终 JSON 和执行目标，再主动执行。

- 首批参数可包含字符串、数值、布尔和日期时间；对象/数组是否首期支持待确认。
- 定义参数名称、类型、必填、默认值、说明；运行时输入与模板定义分开保存。
- 建议用解析后的值节点绑定和类型化赋值，不用原始字符串全局替换拼接 JSON，不执行 JavaScript 或任意表达式。
- 参数替换仅作用于明确标注的值节点；字段名、资源名和请求路径首期不作为隐式替换目标。
- 参数缺失或类型不符时不执行；最终请求重新通过语言、目标和主进程校验。
- Solr 值仍需遵循 Solr 查询转义规则；JSON 转义不能替代原生查询语法转义，规则放在 adapter/语言边界处理。
- 历史保存实际执行的请求快照；模板只保留定义，是否记住上次参数由保存策略控制。
- 日期模板明确时区和范围端点，不把本地日期无提示转换成其他时区。

### WB-08：在兼容连接复用

建议通过“复制到其他连接”创建新草稿，保留原标签。执行前明确选择连接、资源和语言，并校验目标能力。初次复制无需自动连接、查询或写入数据。

字段缺失、引擎版本不同、语言不兼容和连接已删除分别给出可操作提示。不同查询语言不做自动翻译；完整跨引擎迁移属于方向 D 的后续范围。

## 8. 本地保存、敏感内容与容量

查询条件本身可能包含业务敏感值，因此需要同时讨论“历史保存”与“草稿保存”。只关闭历史，不能让用户误以为草稿正文也不会落盘。

建议提供全局默认策略和每连接覆盖：

| 策略 | 建议行为 |
|---|---|
| 正常本地保存 | 自动保存草稿和历史正文；首次清楚说明保存范围，可分别关闭 |
| 仅历史摘要 | 历史保留时间、目标和状态，不保留可重放正文；草稿保存另行显示开关 |
| 本连接不自动保存正文 | 查询正文仅保留在当前内存；草稿、最近关闭、历史都不自动落盘 |

上述默认选哪一个属于待讨论项。手动收藏是独立的明确保存动作；关闭自动保存不会静默删除已有收藏或历史。清理现有记录应由用户明确选择，并覆盖相关恢复快照，避免清空后又从旧草稿恢复。

其他约束：

- 连接凭据、认证头、密码和 API Key 不进入历史/草稿模型；保存连接 ID，不复制完整连接配置或含凭据 URL。
- 自动脱敏无法可靠识别任意业务条件中的秘密，应提供正文保存控制，不声称能够完整脱敏。
- 不默认持久化完整响应、命中文档、错误堆栈或请求日志。
- 保存数量与字节数都要有上限；历史、草稿和收藏分别限额，超限时提供明确处置方式。
- 文本写入采用节流/合并更新，主进程负责校验、版本与写入顺序；不能用每次按键同步写整个无界历史列表。
- 首期可评估继续使用现有 electron-store；若容量或写入成本不满足要求，再依据基准讨论数据库依赖。
- 历史/草稿文件损坏时保留可恢复副本、报告读取失败，允许进入空工作台；不能无提示覆盖旧文件。
- 首期不引入云端同步、遥测或自动上传查询内容。手动分享/导出查询库另行讨论。

## 9. 技术影响范围草图

本节用于讨论可行性与回归范围，不是最终 IPC 设计或可以直接逐步执行的开发计划。需求确认后再确定 API 名称、数据版本和文件拆分。

### 9.1 建议数据边界

| 概念 | 持久化的主要内容 | 仅运行时内容 |
|---|---|---|
| 查询草稿 | 格式版本、标签身份、上下文、目标、语言、文本/表单、顺序、更新时间 | 请求身份、结果、loading、错误详情、分页上下文 |
| 执行历史 | 执行 ID、固定请求快照或摘要、来源、时间、已接受/运行中标记及终态、耗时与命中摘要 | transport、AbortSignal、响应正文 |
| 收藏/模板 | 格式版本、名称、语言、查询、可选参数定义、来源提示 | 当前输入参数、正在执行状态 |
| 结果视图 | 上下文、字段路径片段、列顺序/宽度、视图偏好 | 当前文档数据与选中行 |

草稿和历史应有稳定 ID、格式版本和总量约束。执行 ID 与现有 `requestSeq` 用途不同；恢复时分配新运行时身份，不能复用上次进程的请求序号。

### 9.2 预计涉及的现有模块

| 模块 | 预计职责变化 |
|---|---|
| [src/shared/ipc.ts](../../src/shared/ipc.ts) / [searchEngine.ts](../../src/shared/searchEngine.ts) | 先定义草稿、历史、保存策略、语言信息等明确请求/结果类型；保持查询引擎模型中立 |
| [src/preload/index.ts](../../src/preload/index.ts) / [src/main/index.ts](../../src/main/index.ts) | 注册并暴露有限的读取、保存、删除、清理操作；复用 `window.searchApi` |
| [src/main/store/](../../src/main/store/) | 主进程持久化、数据格式升级、容量/保留策略；新文件名在实施计划确定 |
| [resource.service.ts](../../src/main/services/resource.service.ts) / [resourceIpc.service.ts](../../src/main/services/resourceIpc.service.ts) | 在共同执行边界关联历史生命周期，隔离本地保存失败与服务器查询结果 |
| [dslFavorite.service.ts](../../src/main/services/dslFavorite.service.ts) | 兼容旧收藏，补充语言、迁移与模板参数验证 |
| [workspace.store.ts](../../src/renderer/stores/workspace.store.ts) | 从一次性活动资源状态演进为有边界的上下文/标签状态；保持请求序号与取消保护 |
| [DslQueryPanel.tsx](../../src/renderer/components/DslQueryPanel.tsx) / [SimpleQueryPanel.tsx](../../src/renderer/components/SimpleQueryPanel.tsx) | 草稿状态、执行/停止、历史入口；A2/A3 再接字段与模板辅助 |
| [DocumentPanel.tsx](../../src/renderer/components/DocumentPanel.tsx) / [FieldListPanel.tsx](../../src/renderer/components/FieldListPanel.tsx) | A2 接入展示列和字段选择，保留引擎专有元数据 |
| [tests/unit/](../../tests/unit/) | 为真实状态转换、迁移、竞态、容量和参数行为补充确定性回归测试 |

复用现有 React、Ant Design、Zustand、Monaco、TypeScript 与主进程持久化模式。只有在多个真实查询入口都需要时才提取共享模块，不预先建立插件或通用脚本框架。

### 9.3 必须保持的架构约束

- renderer 不读取文件、不直接连接搜索服务器；持久化和查询均走 typed IPC。
- 新 IPC 先定义在共享层，再同步主进程与 preload，并在产生副作用前做运行时校验。
- 语言、目标、记录 ID、正文大小和批量清理范围必须在主进程验证。
- 查询与 Schema 的引擎差异继续留在 adapter；服务依赖能力契约，UI 根据 capabilities 决定入口。
- 保持 `contextIsolation: true`、`nodeIntegration: false` 和 CSP marker；不引入 renderer 任意代码执行。
- `DslFavorite` 等旧契约需有明确兼容迁移，已有收藏/连接不能因工作台升级丢失。

## 10. 建议验收与验证计划

以下是后续实施时的验收项，本轮均未执行，也不代表已有覆盖。

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-01 | 写入合法/不合法 JSON 草稿，正常重启 | 文本、标题、目标、语言和标签顺序恢复；不自动执行 |
| AC-02 | 连接/资源 A→B→A；标签目标手动改为 C | A/B 各自恢复；C 不被侧栏静默改回；Schema 与真实目标一致 |
| AC-03 | 执行期间编辑、重跑、关闭标签或切换连接 | 旧响应不覆盖新状态；每次执行的历史快照与终态正确 |
| AC-04 | 成功、零命中、401/403、网络错误、取消 | UI 区分状态；历史无凭据、响应正文和原始堆栈 |
| AC-05 | 进程退出时仍有运行记录 | 重启标为中断，不继续显示运行中，不自动重跑 |
| AC-06 | 从历史/收藏恢复到新标签 | 显示真实目标和语言；保留当前草稿；用户再主动执行 |
| AC-07 | 旧收藏和缺少 engineType 的旧连接 | 读取/迁移不丢失；旧连接仍视作 ES；语言不混用 |
| AC-08 | 关闭自动正文保存；清理历史/草稿 | 所有自动恢复路径遵守策略；清理后不会从旧快照复现 |
| AC-09 | 容量上限、超大单条、磁盘不可写、文件损坏 | 有限内存/磁盘占用；有可操作提示；查询结果不受本地保存失败污染 |
| AC-10 | 字符串编号、超长整数、Schema 加载失败 | 值不被错误强转；辅助失败时可继续手动查询 |
| AC-11 | 缺失/null/数组/点号字段/Solr 非 stored 字段 | 展示语义正确；切换视图不重新查询；分页说明真实 |
| AC-12 | 类型参数、引号/反斜杠、缺参、Solr 特殊字符 | 最终请求预览一致；无 JSON 拼接或原生语法逃逸错误 |

AC-01 至 AC-09 对应首期 A1；AC-10/11 对应 A2，AC-12 对应 A3。范围缩减后同步删减验收，不把后续项当作首期必做。

验证分层：

1. 确定性测试：优先覆盖保存/迁移、上下文与请求竞态、历史生命周期、容量淘汰、错误映射；复用现有 [workspaceStore.test.ts](../../tests/unit/workspaceStore.test.ts)、[ipcValidation.test.ts](../../tests/unit/ipcValidation.test.ts) 等测试模式。
2. 源码变更后执行 `npm run typecheck`、`npm test`、`npm run build`。若涉及 Electron 生命周期/打包，再在可用环境执行 `npm run pack` 并记录结果。
3. Electron 手工验证：加载、空状态、成功、失败、取消、恢复、清理确认、快捷键、快速切换与窄窗口；提供与用例对应的记录。
4. 真实服务器验证：覆盖目标版本、语言和认证模式；fixtures、真实服务、桌面验收分别记录，不能互相替代。
5. 性能验证：按最终确认的容量测试启动恢复、输入响应、列表筛选、保存延迟和内存；没有基准前不承诺具体性能数字。

## 11. 首期边界与后续拆分

建议 A1 首期包含：按上下文保留草稿、重启恢复、持久化历史、旧收藏兼容与语言信息、执行/停止状态、正文保存控制，以及对应回归验证。

A2 再处理字段辅助、类型提示、结果列和视图；A3 再处理参数模板与跨连接复用。这样可以先验证恢复模型是否符合用户习惯，再决定是否重做全局工作台。

本次工作台讨论不预先纳入：全功能集群运维、跨环境自动同步、跨引擎查询翻译、百万级可恢复搬运、PIT/深度分页自动切换、任意 HTTP 控制台、云端协作、AI 自动执行、插件市场或新增平台打包。若选中这些需求，回到[方向总览](2026-10-18-product-directions.md)单独评估范围。
